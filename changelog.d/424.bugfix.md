## Spawn-time role prompts are no longer lost silently on slow-booting panes

A role's spawn-time prompt was counted as delivered the moment its bytes reached the pane's PTY. `Applied`/`Queued` only ever meant the write reached the PTY, not that the agent actually submitted it — so against a booting Claude Code pane (SessionStart fires early, then MCP servers start and a hook can emit around 11 KB of output before the input is ready to accept a submit), the prompt could be swallowed entirely. The pane then came up healthy and Idle with no prompt at all, and was silently abandoned 60 seconds later with nothing logged.

Delivery is now provisional: the prompt, its delivery state and retry backoff are retained until a matching `UserPromptSubmit` confirms the agent actually received it, the existing bounded backoff retries the write, and an unconfirmed prompt is still abandoned after the timeout rather than retried forever. Info-level delivery logging was added — written, delivery id, confirmed, unconfirmed, abandoned — visible when `DOT_AGENT_DECK_LOG` is set.

This lands across all three places a spawn-time prompt is delivered: the orchestrator delegate path and the seed-prompt path (both in `src/ui.rs`), and the `dispatch --single` spawn path (`src/spawn.rs`).
